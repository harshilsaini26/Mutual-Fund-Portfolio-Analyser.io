{# The Sankey — the flagship. MODULE_6.md §8.1. Funds on the left, companies on the right, flow width in rupees. It explains look-through in one glance, which is the product thesis. The payload crosses into JavaScript as JSON with **every Decimal still a string** (§15.2). ECharts' sankey series needs numbers for layout, so `charts.js` parses them at the one point where a flow's width is computed — a coordinate, not a figure anyone reads (V1-86; it was d3-sankey before). Every number the user actually sees is formatted here, server-side, and shipped as text. Two hard requirements from Appendix A, both enforced in the builder and asserted in tests: cap at ~40 companies with an aggregated `__OTHERS__` node, and render `__UNRESOLVED__` / `__NO_DISCLOSURE__` as visually distinct nodes pinned outside `top_n`. Missing mass that disappears into "smaller holdings" is the one outcome this project exists to prevent. #} {# §10.4: every chart has an accessible table equivalent reachable from the same view.
